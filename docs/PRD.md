> 版本：v1.1

> 说明：本文档包含首版范围、业务规则和数据结构。第 10 节列出首版暂定口径。

## 1. 背景与目标



集团人力资源人才管理部门需要根据员工的考试记录，自动判定并生成「软件能力认证证书」授予情况表。当前流程依赖人工比对考试记录与证书规则，效率低且易出错。



本工具的目标：



1. 读取员工考试记录（02）与证书规则（03），自动生成应授予的证书（00）。

2. 合并历史已授予证书（01），避免重复。

3. 提供网页端操作，包括汇总证书、批量标记发放状态和按部门导出。

4. 处理考试名称中英文标点、空格不一致等数据质量问题。



首版供集团人力资源人才管理人员使用，在浏览器中处理本次导入的 Excel，并下载结果工作簿。

| 2 | 姓名 | 员工姓名 |

| 3 | 证书名称 | 如「软件开发能力认证证书（工作级，C++）」 |

| 4 | 证书级别 | 入门级 / 工作级 / 专业级 |

| 5 | 证书语言类别 | C / C++ / Java / Go / Python / JavaScript / Rust / ArkTS / C-系统软件 |

| 6 | 是否最高级别证书 | 是 / 否 |

| 7 | 证书获得日期 | YYYY-MM-DD |

## 5. 业务规则（已确认）



### 5.1 证书体系



- 级别：入门级、工作级、专业级。

- 语言：C、C++、Java、Go、Python、JavaScript、Rust、ArkTS、C-系统软件。

- 「C-系统软件」仅有专业级，没有入门级和工作级。

- 各科目要求：

  - 入门级：科目一、科目二。

  - 工作级：科目一、科目二、科目三。

  - 专业级：科目一、科目二、科目三、科目四。

- 科目一、科目二区分编程语言；科目三、科目四不区分编程语言（但专业级科目三有语言专属版本）。



### 5.2 就低原则与高级别覆盖



对某员工某语言，目标级别 L 的每个必需科目，都要存在一条「级别 ≥ L」且符合 5.3 的通过记录。高级别科目可以覆盖低级别同科目。授予级别和日期按 5.5 的同日与增量规则确定。



示例：C 语言科目一通过专业级、科目二和科目三通过工作级 → 获得 C 语言工作级证书（专业级科目一顶工作级科目一，但科目二/三只有工作级）。



### 5.3 跨语言覆盖与科目三/四通用性



- 科目一、科目二：仅同语言覆盖（专业级 C 科目一可顶工作级/入门级 C 科目一，但不能顶 C++ 科目一）。

- 科目三：

  - 工作级科目三为「通用」考试；工作级各语言专属科目三（方式3）也满足工作级科目三。

  - **除 C-系统软件的科目三（系统软件）外，其余专业级科目三（含通用软件、各语言专属）都能顶替工作级通用科目三。**

  - 专业级科目三：同语言专属版本或「通用软件」版本满足；C-系统软件使用「系统软件」版本。

- 科目四：仅「软件设计与重构认证科目（专业级）」一个通用考试，所有专业级证书通用。

- 判定完全以 03 表每行每列列出的考试名为准，不做额外推断。



### 5.4 证书判定算法



对每个员工、每个语言（含 C-系统软件）：



1. 从 02 中筛选「状态=通过」的记录。

2. 将每条考试名称按 03 表映射为（科目、级别、语言）。科目三/四为跨语言共享。

3. 对每个目标级别 L（入门级/工作级/专业级）：

   - 确定必需科目集合。

   - 对每个必需科目，找出所有满足条件的通过记录（级别 ≥ L，且符合 5.3 的覆盖规则），取其中**最早**的通过日期。

   - 若某必需科目无满足记录，则该级别不可凑齐。

   - 若全部满足，该级别的「凑齐日期」= 各必需科目最早日期中的**最大值**（即凑齐该证书的最后一科日期）。

4. 应用同日规则（见 5.5）。

5. C-系统软件仅判定专业级，科目为：科目一（C-系统软件）、科目二（C）、科目三（系统软件）、科目四（通用）。



### 5.5 增量发放与同日规则



按考试通过日期从早到晚推进，某级别首次可凑齐的日期即该证书获得日期。



- **同一天**可凑齐多个级别时，只发最高级别。

- **不同日期**凑齐的级别，分别发放，各自使用自己的凑齐日期。

- 示例：

  - 专业级科目一/二先过（第 1 天）→ 入门级；再过科目三（第 2 天）→ 工作级；再过科目四（第 3 天）→ 专业级。三张都发。

  - 科目二、科目三同一天通过 → 入门级与工作级同日凑齐 → 只发工作级。

  - 专业级科目二/三/四先过，最后过科目一 → 三张同日凑齐 → 只发专业级。

  - 入门级科目一/二 + 工作级科目三（凑不齐工作级）→ 只发入门级。



形式化：对每个可凑齐的级别计算凑齐日期；若存在更高级别与其同日，则跳过该低级别；否则发放。



### 5.6 历史证书合并



- 01 历史证书**不重新计算**，保留原记录与原日期。

- 将 01 中「未重复」的证书合并到 00。

- 证书唯一键为「工号 + 证书级别 + 标准化语言类别」。由规范化后的证书名称识别级别和语言，按该键合并 01 与 02，重算时也用该键匹配输入 00。工号保留前导零，语言别名按 5.9 处理。

- 重复时保留**较早**的日期。

- 即使 01 已有更高级别证书，02 在另一日期凑齐的低级别证书仍可生成（按 5.5 规则）。

- 证书名称前缀统一为「软件开发能力认证证书（…）」（去掉「华为」前缀）。



### 5.7 是否最高级别证书



- 按**员工本人**判定，**不区分语言**。

- 该员工所有证书（含 01 历史与 02 新生成）中，最高级别（专业级 > 工作级 > 入门级）的证书标「是」，其余标「否」。

- 若同一员工有多张同一最高级别的证书（如 C 专业级 + Java 专业级），**都标「是」**。



### 5.8 名称标准化



考试名称、证书名称可能出现中英文括号、逗号、空格不一致。匹配前统一标准化：



1. 去除首尾空白；

2. 全角括号 `（）` → 半角 `()`；

3. 全角逗号 `，`、顿号 `、` → 半角 `,`；

4. 去除所有空格（含全角空格 `\u3000`）。



标准化后用于匹配；展示时保留原始写法（证书名称按 5.6 统一前缀）。



**注意**：标准化仅用于匹配，保留原始数据。名称和日期的辅助值保存在处理过程中，导出的 01、02、03 保留原有字段和值。



### 5.9 命名与脏数据处理



- **JavaScript 与 JavaScript&TypeScript 视为同一语言**，统一按「JavaScript」处理。

- 03 表 R24 证书名「ArkTSt」为笔误，按「ArkTS」处理。

- 03 表「C-系统软件」证书的科目二写的是「软件编程知识与应用认证科目（专业级,C）」，这是事实，不是笔误。

- `考试标准名称` R86 编码与 R84 重复，忽略该表，不影响判定。

- 02 中「是否有效」列忽略，只按「状态=通过」过滤。

- 02 中「交卷时间」大多为空，证书获得日期取「开始答题时间」，仅保留年月日。



### 5.10 重算、生成时间与发放状态



- 单工作簿汇总用当前工作簿的 01、02、03 计算结果，用当前 00 作为比对基线。首次导入时使用 Excel 中的 00。同一工作簿在页面内再次汇总时，使用页面内上次汇总及标记后的 00。00 为空时，所有证书按新增处理。双工作簿换版使用上次正式汇总的 00，流程见 6.4。

- 用户在页面点击「汇总」按钮时，工具运行整体逻辑生成 00 表；本次运行时间记为 `run_time`（格式 `YYYY-MM-DD HH:mm:ss`）。

- 同一证书按 5.6 匹配。只要本次结果仍有这张证书，就沿用输入 00 中该证书的发放状态，包括获得日期变化的情况。输入 00 中无对应记录时，发放状态留空。

- 生成时间按以下规则确定。部门、最高级别标记和发放状态可独立变化，沿用原生成时间。

  - 新出现的证书记录（含首次导入的历史证书）：生成时间 = 本次 `run_time`。

  - 同一证书的获得日期相同且旧值有生成时间：沿用旧生成时间。

  - 同一证书的获得日期变化，或旧生成时间为空：生成时间 = 本次 `run_time`。

  - 输入 00 独有、经本次重算和历史合并后未出现的证书从结果中删除。

- 调整 03 后重算时，使用同一套规则。



### 5.11 部门取值



- 按工号比较 01 的证书获得日期和 02 的开始答题时间，统一采用最新一条带有 0层部门的记录。以同一行的 0层和一层部门为一组，一层缺失留空。
- 00 填写该部门，按部门导出 00/01/02 时也按该部门筛选员工。导出的 01 和 02 保留各自原始部门列。

## 6. 功能需求



### 6.1 证书生成



**输入**：包含 00/01/02/03 的 Excel 工作簿（或等价数据）。



**触发方式**：用户在页面点击「汇总」按钮触发；本次运行时间记为 `run_time`，用于 5.10 的生成时间。



**处理流程**：



1. 读取原始工作簿，在浏览器中建立工作副本。磁盘上的原始文件只读。

2. 从 02 的「开始答题时间」提取 `YYYY-MM-DD` 格式的考试日期，按 5.8 规范化考试和证书名称。辅助值用于当前汇总。

3. 按 5.4–5.7 判定与合并证书，并按 5.11 取部门。

4. 00 为空时按首次汇总处理，生成时间写本次运行时间，发放状态留空。00 已有证书记录时按 5.10 比对，确定每条记录的生成时间和发放状态。

5. 将 12 列表头和证书记录写回同一个工作簿的 00 表，保留 01、02、03 和其他原有工作表。

6. 用户下载包含更新后 00 和原有数据表的完整工作簿。后续可在该工作簿里补充 01 或 02 的记录，再导入工具重算。



**输出**为完整的 Excel 工作簿。其中 00 表的 12 列按 4.1 定义，其余工作表保留原有数据。



### 6.2 批量标记发放状态



- 网页提供【证书发放状态】按钮。

- 支持批量粘贴员工工号（每行一个）。

- 按工号搜索 00 表中的证书记录。

- 批量标记为「已发放」或「未发放」，写入结果工作簿的 00 表。下次导入该工作簿时，同一证书沿用所保存的标记。

- 未匹配到的工号给出提示。



### 6.3 按部门导出



- 按 5.11 确定的员工部门导出 00/01/02 三个表。一层部门以「0层部门 + 一层部门」识别。

- 提供复选框选择要导出的表，默认三个全选。

- 无一层部门的员工按 0层部门归组。

- 输出为一个只包含该部门数据的工作簿，Sheet 与原来一致（00/01/02）。

### 6.4 双工作簿换版核对

- 选择上次正式汇总及本次客户的完整工作簿，核对两版 01、02 的记录变化和 03 的规则变化，并以新版 01、02、03 预览 00。
- 同一证书从上次正式汇总的 00 继承生成时间和发放标记。新版 00 的非空标记存在差异时，用户选择采用哪一版的这些标记。
- 用户确认同范围的完整供数，并核对曾标记已发放但本次未生成的证书后，下载更新了 00 的新版副本。副本保留新版 01、02、03 和其他工作表。来源配对方式见[产品说明](PRODUCT.md)。

## 7. 输出规格



00 表 12 列，字段取值：



| 字段 | 取值 |

|---|---|

| 工号 | 来自 02（新证书）或 01（历史证书） |

| 姓名 | 同上 |

| 证书名称 | `软件开发能力认证证书（{级别}，{语言}）` |

| 证书级别 | 入门级 / 工作级 / 专业级 |

| 证书语言类别 | C / C++ / Java / Go / Python / JavaScript / Rust / ArkTS / C-系统软件 |

| 是否最高级别证书 | 是 / 否（按 5.7） |

| 证书获得日期 | YYYY-MM-DD（按 5.4/5.5/5.6） |

## 8. 非功能需求



- **形态**：内网网页工具，在浏览器端读取、处理和导出 Excel。

- **数据量**：约 1.3 万条考试记录、2600+ 员工，处理应在秒级完成。

- **数据处理**：员工和证书数据在浏览器中处理，跨次状态保存在结果工作簿内。

- **文件处理**：原始 Excel 只读，处理后的工作簿供用户下载。

- **界面语言**：中文。

- **可维护性**：规则表（03）应可配置/可替换，避免硬编码考试名称。

- **可追溯**：生成结果应能追溯到具体考试记录（建议保留匹配明细，便于核对）。

## 9. 验收标准



1. 使用样例数据生成 00，证书级别、语言、日期符合 5.4–5.6。

2. 同日规则验证：同日凑齐多级别只发最高级；不同日分别发放。

3. 高级别覆盖验证：专业级科目一顶工作级/入门级科目一；专业级科目三（除系统软件）顶工作级通用科目三。

4. 历史合并验证：01 与 02 按「工号 + 证书级别 + 标准化语言类别」去重，保留较早日期。

5. 最高级别标记验证：按员工跨语言取最高级别；同级别多张都标「是」。

6. 名称标准化验证：全角/半角括号、逗号、空格不一致的考试名能正确匹配。

7. JS 与 JS&TS 视为同一语言。

8. 批量标记：粘贴工号后正确标记，未匹配工号有提示。

9. 部门导出：按最新部门筛选。缺少一层部门的员工按 0层部门归组。复选框控制导出表。

10. 文件往返：导入完全空白的 00 表后，下载的工作簿在 00 中包含 12 列表头及汇总结果。01、02、03 的字段和值保持一致。再次导入时，仍存在的同一证书保留发放状态。

11. 生成时间：同一证书的获得日期相同时沿用旧值。新增、获得日期变化或旧生成时间为空时写入本次运行时间。输入 00 独有且重算后未出现的证书从结果移除。

## 10. 首版暂定口径



1. 00/01/02/03 随同一个 `.xlsx` 工作簿导入。首次使用时，00 可以完全空白，也可以只有表头。
2. 只有证书获得日期变化会刷新已有证书的生成时间。部门、最高级别标记和人工发放状态各自更新。
3. 暂按员工在 01 或 02 中较晚的记录确定部门，00 和按部门导出共用该结果。日期时间相同时，优先使用 02 的部门。
